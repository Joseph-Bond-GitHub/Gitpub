Week 1

Database foundations, ER models and JDL

Core definitions

Database
A collection of related data, such as students, modules and enrolments.
DBMS
Software for storing, organising, retrieving, updating and controlling data, e.g. PostgreSQL.
Schema vs data
Schema describes tables, types and constraints; data is the actual rows stored.
Relational vs graph
Relational data uses tables and SQL; graph data uses nodes/relationships and languages such as Cypher.

Why a DBMS? Less redundancy and inconsistency, shared access, integrity constraints, structured management and controlled permissions.

Database design flow

Requirements analysis → conceptual design → logical design → schema refinement → physical design → application integration/security.

Keys and ER cardinality

ConceptMeaningTypical example
Primary key (PK)Uniquely identifies each rowstudent_id
Foreign key (FK)References a key in another tablestudent.program_id → program.program_id
1:1Each instance relates to at most one on the other sidePerson ↔ Passport
1:MOne record has many related recordsLecturer → Modules; FK on many side
M:MMany records relate to many othersStudents ↔ Modules; junction table

An entity is something recorded (Student), an attribute is a property (email), and a relationship describes a connection (Student enrols in Module). Cardinality and optionality indicate how many can participate.

JDL essentials

entity Student {
  name String required,
  email String required unique,
  dateOfBirth LocalDate
}
entity Module {
  title String required
}
relationship ManyToMany {
  Student{modules} to Module{students}
}

JDL is JHipster Domain Language. Field syntax is name Type modifier. Common modifiers include required, unique, min, max, minlength and maxlength. Naming both ends of a relationship in braces enables navigation both ways in generated code.

Exam trap: A relational many-to-many normally needs a junction table, not a single foreign-key field on one side.

Week 2

Normalisation · UNF to 3NF

Goal: organise data to avoid duplicated information and insertion, update and deletion anomalies.

FormRequirement emphasised in lecturesViolation to look for
1NFAtomic (single) values in cells; no repeating groups; identifiable rows / primary keyOne cell holds several phone numbers, or columns Class1, Class2, Class3
2NF1NF + every non-key attribute depends on the whole composite keyNon-key attribute depends on only part of a composite key
3NF2NF + remove transitive non-key dependenciesKey → non-key A → non-key B

Know the dependency vocabulary

Functional dependency: X → Y means X determines Y. Partial dependency: an attribute depends on only a subset of a composite candidate key. Transitive dependency: a non-key value is determined through another non-key value.

Worked 2NF example

Suppose Enrolment(student_id, module_id, student_name, module_title, grade) has composite PK (student_id, module_id).

AttributeDependencyDestination
student_namestudent_id → student_nameStudent(student_id, student_name)
module_titlemodule_id → module_titleModule(module_id, module_title)
gradeDepends on student + module togetherEnrolment(student_id, module_id, grade)
Correct 2NF fix: separate partially dependent attributes into a table keyed by their determinant. Do not key the new table by the entire composite key—that would preserve the partial dependency.

Worked 3NF example

If Student(student_id, name, postcode, city) has a rule postcode → city, then student_id → postcode → city. Under that stated rule, separate to Student(student_id, name, postcode) and Postcode(postcode, city).

Quick distinction: Multivalued cells → 1NF issue. Partial composite-key dependence → 2NF issue. Non-key → non-key dependence → 3NF issue.

Week 2 · Practical

PostgreSQL and SQL foundations

PostgreSQL is the relational DBMS; SQL is the query language; psql is a PostgreSQL command-line client. SQL statements usually end with ;, while psql meta-commands start with a backslash.

-- SQL: table definition
CREATE TABLE student (
  student_id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  email TEXT UNIQUE
);

-- SQL: CRUD (create/read/update/delete rows)
INSERT INTO student (student_id, name)
VALUES (1, 'Aisha');
SELECT * FROM student;
UPDATE student SET name = 'Aisha Khan'
WHERE student_id = 1;
DELETE FROM student WHERE student_id = 1;

-- psql examples (NOT SQL statements)
\c database_name
\d student
Constraints
PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, DEFAULT keep data valid.
Access control
CREATE ROLE, GRANT and REVOKE manage permissions. Use least privilege.
Safety: UPDATE or DELETE without a suitable WHERE can affect every row. Prepared/parameterised queries prevent SQL injection by treating input as data.

Week 3

Advanced SQL · Queries, functions and constraints

Common query patterns

-- Count matching rows
SELECT COUNT(*) AS total
FROM books
WHERE publication_year < 1900;

-- Sort, greatest first
SELECT title, publication_year
FROM books
ORDER BY publication_year DESC;

-- Group and filter groups
SELECT category, COUNT(*) AS book_count
FROM books
GROUP BY category
HAVING COUNT(*) > 5;
Clause / functionUseRemember
WHEREFilters individual rowsBefore grouping
GROUP BYMakes groups of matching valuesOften with aggregates
HAVINGFilters grouped resultsAfter grouping
COUNT(*)Counts rowsIncludes rows with NULLs
COUNT(column)Counts non-NULL valuesDoes not count NULLs
SUM / AVG / MIN / MAXAggregate numerical data / extremesIgnore NULL inputs
ORDER BY ... ASC / DESCSorts outputAscending / descending
ASNames a result column or aliasImproves readability

Changing database structures

ALTER TABLE student
ADD CONSTRAINT fk_student_program
FOREIGN KEY (program_id) REFERENCES program(program_id);

CREATE VIEW active_tasks AS
SELECT * FROM todo_item WHERE completion_date IS NULL;

PREPARE find_student (INTEGER) AS
SELECT * FROM student WHERE student_id = $1;
EXECUTE find_student(1);

Import formats: CSV, TSV, JSON and XML. Index: a database structure that can accelerate lookups; PK and UNIQUE constraints automatically create indexes in PostgreSQL. View: a stored query presented as a virtual table. Prepared statement: SQL with parameters supplied when executed.

DROP removes an object such as a table; TRUNCATE removes all rows while keeping the table structure; DELETE can remove selected rows. PostgreSQL PL/pgSQL adds procedural control structures, and DO executes a one-off anonymous block.

Weeks 3–4

SQL JOINs · High-priority topic

JOIN typeWhat you getUnmatched records?
INNER JOINOnly matching rows on both sidesNo
LEFT JOINAll left rows + matching right rowsUnmatched right fields become NULL
RIGHT JOINAll right rows + matching left rowsUnmatched left fields become NULL
FULL OUTER JOINMatched + unmatched rows from both sidesNULLs where there is no partner
NATURAL JOINAutomatically joins equally named common columnsBe careful which column names overlap
-- Match each student to a program
SELECT s.name, p.program_name
FROM student AS s
INNER JOIN program AS p
  ON s.program_id = p.program_id;

-- Keep every student, including those with no program
SELECT s.name, p.program_name
FROM student AS s
LEFT JOIN program AS p
  ON s.program_id = p.program_id;

-- Find students with no matching program
SELECT s.name
FROM student AS s
LEFT JOIN program AS p
  ON s.program_id = p.program_id
WHERE p.program_id IS NULL;

NULL is not 0. It denotes missing/unknown/inapplicable data. Test with IS NULL or IS NOT NULL, not = NULL. A LEFT JOIN can appear identical to an INNER JOIN when every left row matches.

Week 4

ORM, JPA, Hibernate and Liquibase

Distinguish the technologies

ORM
The idea of mapping relational rows/tables to program objects/classes.
JPA / Jakarta Persistence
The specification/API defining entities, relationships and persistence operations.
Hibernate
An implementation of JPA that performs mapping and generates SQL.
Spring Data JPA
Repository abstractions supplying methods such as save(), findById(), findAll() and deleteById().

Connection: Application / repository → JPA contract → Hibernate → JDBC → relational database. Table → class, row → object, column → field, FK → object reference.

@Entity
@Table(name = "student")
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @ManyToOne
    @JoinColumn(name = "program_id")
    private Program program;

    protected Student() {}  // JPA no-arg constructor
}
Annotation / termRemember
@Entity, @TableMaps a Java class to a table
@Id, @GeneratedValuePrimary key / generated identifier
@ColumnMaps field details to a column
@ManyToOne, @JoinColumnMany side owns FK (e.g. Student → Program)
@OneToMany(mappedBy = "program")Inverse Java-side collection; points to owning field
@ManyToMany, @JoinTableMany-to-many through a join table
EntityManagerpersist, find, merge, remove
Persistence contextTracks managed objects; changed managed entities can be written at flush/commit
EAGER / LAZYWhen relationships are fetched; lazy access outside a context can fail

JPQL versus SQL

-- SQL uses tables and columns
SELECT * FROM student WHERE student_id = 1;

-- JPQL uses Java entities and fields
SELECT s FROM Student s WHERE s.id = :id

Liquibase

Liquibase versions database schema changes via ordered changelogs and changesets. Hibernate/JPA maps and manipulates data at runtime; Liquibase applies changes to the table structure. Editing an already-run changeset can cause a checksum mismatch. The lecture recommends schema validation or no automatic schema updates in production rather than relying on ddl-auto: update.

Likely theory contrasts: ORM ≠ JPA ≠ Hibernate; @ManyToOne owns the FK; managed vs detached entities; JPQL names Java fields rather than database columns; Liquibase changesets version schemas.
Source: Week4_JPA_Hibernate.pptx, ORM, JPA annotations, repositories, lifecycle, relationships, JPQL and Liquibase.
Self-check · Theory

Quick concept questions

Try answering before opening each explanation. These are newly written revision prompts, not copied test questions.

1. A table has (student_id, module_id) as PK. student_name depends only on student_id. Which normal form is violated?
2NF. This is a partial dependency on only one part of a composite key. Move student_name to a Student table keyed by student_id.
2. A column stores “red, blue, green” in one cell. Which normal form is at issue?
1NF. The cell contains multiple values rather than one atomic value.
3. Student ID determines postcode and postcode determines city. What issue can arise?
3NF / transitive dependency if postcode and city are non-key attributes under the stated functional-dependency rule.
4. Which JOIN keeps all records from the first table?
LEFT JOIN. Columns from the right table are NULL for unmatched rows.
5. Does COUNT(column_name) count NULL entries?
No. COUNT(column_name) counts non-NULL values; COUNT(*) counts rows.
6. Is Hibernate the same thing as JPA?
No. JPA defines the specification; Hibernate implements it.
7. On which table is a foreign key for Student → Program (many students to one program)?
Student. The FK is on the many side, mapped by @ManyToOne / @JoinColumn.
8. What is the difference between WHERE and HAVING?
WHERE filters rows before grouping; HAVING filters groups after aggregation.
Self-check · SQL

Coding-question method and drills

Four-step SQL method

  1. Read the verb: “how many?” → COUNT(*); “list?” → SELECT columns; “highest?” → MAX() or ORDER BY ... DESC.
  2. Find actual table/column names from the provided script (books vs book; year vs publication_year).
  3. Translate exact wording: “before 1900” → < 1900, not <= 1900.
  4. Run the query and verify the output, NULLs, duplicates and filters; do not guess a number.
